# Design\n\n## Context\nThe PLG loop must balance massive top-of-funnel value generation with strict cost controls and data protection. We cannot afford Denial of Wallet (DoW) attacks from bots generating expensive LLM reports, nor can we leak premium Go-To-Market (GTM) data to the client.\n\n## Goals\n- Enable frictionless 'Reverse Demo' functionality.\n- Ensure massive organic reach via SSR-based Programmatic SEO.\n- Protect against scraping and API cost overruns.\n\n## Non-Goals\n- Deep analytics or post-generation workflow tools (handled in subsequent product phases).\n- Manual SEO metadata creation by users.\n\n## Decisions\n- **Cost Control**: Unauthenticated requests will strictly use Gemini Flash-Lite or retrieve pre-generated cached reports.\n- **Teaser Mechanics**: Use CSS `backdrop-filter: blur(8px)` over dummy/placeholder text. The actual premium data (Competitor weaknesses, GTM strategy) will NEVER be sent in the JSON payload to unauthenticated clients.\n- **Auth Linking**: Use React 19 `useActionState` and an `isMergingRef` to handle the dual-token linking (Firebase `signInAnonymously` to full Auth) without UI flicker.\n- **SEO**: Public artifacts must be fully Server-Side Rendered (SSR). Background jobs will handle all `<title>`, description, and JSON-LD generation.\n\n## Risks & Trade-offs\n- **Bot Abuse**: Mitigated via Firebase App Check (reCAPTCHA v3) on the Express BFF to block looping scripts.\n- **Database Bloat**: Unauthenticated sessions will create a ghost session in Firestore (`pqlState`) with a strict 72-hour TTL policy.\n- **Niche Collisions**: Managed by pivoting users to abundance. If a niche is locked, the system denies access and suggests 3 adjacent untapped niches.
