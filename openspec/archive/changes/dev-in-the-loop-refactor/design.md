# Design: Developer in the Loop

## Context

Our OpenSpec workflow must introduce a safe "developer-in-the-loop" staging paradigm that prevents AI agents from executing unchecked architectural mutations while gracefully degrading to support headless systems.

## Goals

- Implement a two-phase commit system (Stage -> Apply).
- Prevent TOCTOU vulnerabilities during application.
- Provide an escape hatch for headless CI/CD (`--force`).
- Implement context recovery since LLMs frequently drop temporary IDs from chat memory.

## Non-Goals

- We explicitly reject relying on Claude Code native `PreToolUse` hooks to avoid vendor lock-in and breakage in other IDEs like Cursor.

## Decisions

- **Partial File Hashing**: The `commit_token` will be generated by hashing ONLY the specific working directory files affected by the `FsIntent`, avoiding anti-pattern false-positive rejections caused by hashing the whole `openspec/` dir.
- **Preview Generation (`git diff`)**: We will use `spawnSync` + `fs.openSync` to pipe `git diff --no-index` directly to `.tmp/openspec_<token>/preview.diff`. This circumvents V8 string length limits and `ENOBUFS` crashes when staging massive file trees. Note: `git diff --no-index` naturally exits with code `1` when differences exist, so the executor must gracefully handle `status === 1`.
- **Chat-Gated Soft Boundary**: Agents will be strictly prompted to execute `--stage`, wait for natural language developer approval (pointing them to `preview.diff`), and then execute `apply --token=<token>`.
- **JSON Stdout Draining**: To avoid truncating the JSON output, `process.exit(1)` will be refactored to use `process.exitCode = 1`, ensuring Node.js flushes the standard streams synchronously.
- **Status Recovery Command**: To prevent token hallucination when context windows shift, `openspec status` will list pending `.tmp/` patches.

## Risks & Trade-offs

- _Risk_: A buildup of `.tmp/` staging files.
- _Mitigation_: A pre-stage cleanup function purges `.tmp/` artifacts older than 24 hours.

## Future Potential

- **MCP Wrapping**: To eliminate string-based CLI hallucinations, we will wrap the CLI logic in a Model Context Protocol (MCP) server, exposing strongly typed `openspec_stage`, `openspec_status`, and `openspec_apply` tools.
