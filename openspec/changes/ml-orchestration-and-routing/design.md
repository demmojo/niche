# Design: ML Orchestration, Model Routing, and Prompt Engineering\n\n## Context\nNicheAI relies heavily on AI features, but treating all requests equally creates system bottlenecks and cost overruns. We need an orchestration layer that applies the right model to the right problem safely and asynchronously, utilizing persistent queuing and a safe API versioning strategy.\n\n## Goals\n- Implement a 3-tier capability routing system using the `gemini-3.1` family.\n- Require CO-STAR standardized prompt interfaces.\n- Safely manage execution via a persistent datastore (Redis/BullMQ) and worker heartbeat patterns.\n- Define a backward-compatible API migration path for existing synchronous endpoints.\n- Clarify 429 rate-limit escalation to prevent dangerous cascading limits.\n\n## Non-Goals\n- Multi-provider load balancing out of scope for Phase 1.\n- Fine-tuning custom models.\n\n## Decisions\n1. **Model Tiering Structure:** Lite Tier (`gemini-3.1-flash-lite-preview`), Fast Tier (`gemini-3.1-flash`), Pro Tier (`gemini-3.1-pro-preview`).\n2. **Prompt Construction:** Refactor `promptAssembler.ts` to strictly require `COSTARPrompt` properties.\n3. **Concurrency & Execution (Revised):** Replace in-memory `p-queue` with a persistent Redis-backed queue (e.g., BullMQ). This resolves architectural contradictions and properly supports distributed workerId leasing and HTTP 202 architectures with zero data loss.\n4. **API Versioning:** Introduce `/v2/async/` endpoints for HTTP 202 interactions. Legacy `/v1/` endpoints will be maintained in a backward-compatible manner (blocking/sync) but marked as deprecated, avoiding a big-bang migration.\n5. **Rate Limiting Strategy:** On HTTP 429, apply exponential backoff and jitter. Crucially, do NOT escalate to a more expensive tier (e.g., Lite to Pro) upon 429 exhaustion, as this causes cost explosions and cascading rate limits. Instead, fail gracefully or fallback to a redundant region of the same tier.\n\n## Risks/Trade-offs\n- **Risk:** Distributed queue overhead.\n - **Mitigation:** Use managed Redis instance to simplify operations.
