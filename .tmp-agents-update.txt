- **Fail-Safe Rollbacks (Application Ledger)**: AI execution is non-deterministic. Before mutative writes (`fs.cpSync`), backup targets to a temporary ledger. If an error or crash occurs, iterate the ledger to rollback all files to their original state to prevent corrupted split-brain states.
- **Headless Reliability & Process Lifecycles**: Never use raw `process.exit(1)`. The outermost CLI entrypoint must use a `safeExit` wrapper that ensures `stdout` and `stderr` buffers drain completely. However, internal library functions (like `FsExecutor`) MUST NOT call `safeExit` or `process.exit`; they must throw structured errors to prevent accidentally killing persistent Express/Cloud Run worker processes if the library is imported elsewhere.
- **CLI safeExit Testing**: When testing `process.exit` inside asynchronous stream drain callbacks (`process.stdout.write(..., cb)`), catch the mocked exception inside the callback and `resolve()` the wrapper's promise. Relying on `rejects.toThrow` will cause hung tests or unhandled rejections.
- **Large Payload Resiliency (Claim Check)**: If the CLI's `--json` payload output exceeds 100KB (e.g., massive diffs), it MUST write the payload to a temporary file and emit a "Claim Check" reference (`{ "claimCheckPath": "/tmp/payload.json" }`) to `stdout` to prevent downstream webhook/Express limits from crashing.
- **Strict Trust Boundary & TOCTOU**: Enforce absolute path resolution (`getSandboxPath`) for all sandbox operations to prevent directory escape. Use strict SHA-256 content hashing for TOCTOU drift detection instead of brittle `mtime` checks. The Staging Token MUST encode these hashes so that `apply` can strictly verify target files haven't drifted between `--stage` and `--apply`.
- **Git Branch Naming**: Never prefix temporary Git branch names with a dot (`.`), as Git strictly rejects this format. Use semantic alphanumeric prefixes (e.g., `openspec-staging-`).
- **ESM File Descriptor Mocking**: Never mutate Node.js `fs` imports directly (`fs.openSync = ...`) to track file descriptors in tests, as ESM modules are immutable. Always use `vi.mock("fs", async (importOriginal) => ...)` to safely wrap target functions and track `EMFILE` leaks in `afterEach`.
- **Concurrent E2E Test Isolation**: When testing filesystem intents in Vitest, NEVER use a shared `.tmp/` directory. Each test block MUST generate a unique, UUID-based sandbox path (e.g., `.tmp/${randomUUID()}`) to prevent race conditions and cross-test corruption during parallel execution.
