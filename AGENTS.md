### CLI Robustness & Filesystem Hardening

- **Anti-Pattern (Vitest `fs` Mocking & Parallel Execution)**: Mocking the ESM `fs` module using memory filesystems like `memfs` for CLI tests, relying on shared `.tmp/` directories for parallel Vitest blocks, or expecting `rejects.toThrow` to catch errors in asynchronous stream drain callbacks that invoke `process.exit`.
- **Resolved Pattern**: Use `vi.mock("fs")` to wrap target functions and accurately track file descriptors, asserting zero `EMFILE` leaks in `afterEach`. Each concurrent Vitest test block MUST generate a unique UUID-based sandbox path (e.g., `.tmp/[ExpiryTimestamp]-[UUID]`) to prevent race conditions. When testing `process.exit` inside async stream drain callbacks, catch the mocked exception inside the callback and manually `resolve()` the wrapper's promise to prevent unhandled rejection hangs.
- **Anti-Pattern (EXDEV/ENOTEMPTY & Atomic Directory Swapping)**: Attempting to `fs.renameSync` a populated staging directory directly over an existing active directory (like `node_modules`), which fails with `ENOTEMPTY` (or `EXDEV` across mount points), or attempting to manage partial failures with brittle Write-Ahead Logs (WAL) and manual rollback loops.
- **Resolved Pattern**: Implement **Atomic Directory Swapping**. All operations occur in an isolated `.tmp/[UUID]` staging directory. To apply, sequentially rename live workspace directories (e.g., `node_modules` to `_old_[UUID]`), then rename the staging directories into their final positions. Finally, asynchronously delete the `_old` directories. This achieves O(1) POSIX atomicity and completely eliminates split-brain corruption without throwing `ENOTEMPTY`. If `EXDEV` occurs, fallback to `fs.promises.cp` and `rm`.
- **Anti-Pattern (EPIPE Swallowing for JSON Payloads)**: Letting `EPIPE` exceptions bubble up and crash the Node.js process when downstream consumers (like `jq` or `head`) close the IPC pipe before the CLI finishes writing a large JSON payload to `stdout`.
- **Resolved Pattern**: Bind an `.on('error')` handler to `process.stdout` specifically to swallow `EPIPE` errors during JSON payload emission, executing `process.exit(0)`.
- **Anti-Pattern (Avoiding `worker_threads` for Regex Overhead)**: Offloading regex-based secret scanning or line-by-line parsing to a `worker_threads` pool in an attempt to prevent main-thread event loop starvation. This introduces massive IPC serialization overhead, premature abstraction, and V8 OOM memory bloat on large codebases.
- **Resolved Pattern**: Execute chunked, line-by-line streaming scanners synchronously on the main thread. Prevent ReDoS by strictly using fixed-window overlapping streams (sized to the maximum expected secret length) and pre-audited, safely bounded JS regex patterns containing zero nested quantifiers. Enforce a strict per-file size limit (e.g., 2MB) to prevent Event Loop starvation natively.
- **Anti-Pattern (The DX Trap of `--ignore-scripts`)**: Hardcoding `npm ci --ignore-scripts` as an immutable security mechanism for staging directory dependency hydration without an escape hatch. This creates a silent DX trap where consumer projects relying on `postinstall` scripts for native binaries (e.g., Prisma, esbuild) mysteriously fail to compile during the staging phase.
- **Resolved Pattern**: Secure the staging environment by defaulting to `--ignore-scripts`, but introduce an explicit `--allow-scripts` opt-in flag. This preserves zero-trust execution by default while providing a conscious escape hatch for projects that legitimately require native binary compilation during staging.
- **Anti-Pattern (Process Lifecycle & Crash-Only Design)**: Trapping `SIGINT` (Ctrl+C) or OOM exceptions to run synchronous file I/O teardown logic, which frustrates users and escalates to untrappable `SIGKILL`s resulting in permanently orphaned Git worktrees.
- **Resolved Pattern**: Embrace a **Crash-Only Ephemeral State** philosophy. Let the process die instantly on `SIGINT` or OOM. Rely on an asynchronous, non-blocking boot-time sweep (`fs.promises.opendir`) on the _next_ execution to garbage-collect expired `.tmp/` directories, explicitly swallowing `ENOENT`, `ENOTEMPTY`, `EBUSY`, and `EPERM` to prevent CI race conditions.
- **Anti-Pattern (Credential Hygiene & Ephemeral `.npmrc`)**: Injecting NPM registry authentication tokens into the global `process.env` (which leaks to untrusted child processes via `/proc/<pid>/environ`) or writing an `.npmrc` with secrets to the live workspace disk.
- **Resolved Pattern**: Securely provision an ephemeral `.npmrc` inside the local `.tmp/[UUID]/` staging directory with strict `0600` permissions. Execute `npm ci` with `--userconfig=${localStagingNpmrcPath}` and `--globalconfig=${platformNullDevice}`.
- **Anti-Pattern (Stdio Isolation & Payload Dumps)**: Emitting human-readable logs directly to `stdout`, mixing them with JSON payloads, or throwing fatal `E_PAYLOAD_TOO_LARGE` errors when output JSON payloads grow too large for downstream webhook limits.
- **Resolved Pattern**: Implement a `StdioRouter`/`TerminalPresenter` that strictly routes all human-readable diagnostics (including deprecation warnings) to `stderr`, reserving `stdout` exclusively for valid JSON payloads. For large outputs, use the **Claim Check** pattern: stream the actual JSON payload to disk and emit a deterministic pointer (`{ "payloadDumpPath": "..." }`) to `stdout` to ensure deterministic V8 memory stability.

### Telemetry & Analytics Architecture

- **Anti-Pattern (Over-Engineering Protocols)**: Implementing over-engineered, non-standard protocols (like Sovereign Blob Reference Protocol/SBRP for massive traces) before standard API patterns fail or before physical data limits strictly require such decoupled data-plane compliance.
- **Resolved Pattern**: Apply the "Minimum Lovable Product (MLP)" and "Binary Triage" mindset to architectural RFCs as well. Strictly reject over-engineered infrastructure and fallback to standard, proven, simple API payloads until physical limits dictate otherwise. Over-engineering for <0.1% edge cases (like 100MB+ traces) introduces unnecessary attack vectors (SSRF, decompression bombs) and maintenance burden.
- **Anti-Pattern (Event Loop Starvation)**: Implementing high-frequency telemetry ingestion, flagging, or batching directly within the Node.js application layer. This blocks the single-threaded event loop, directly degrading the core user experience and tying observability overhead to application performance.
- **Resolved Pattern**: Decouple telemetry ingestion at the infrastructure level. Route high-volume event data through GCP Cloud Tasks (PauseQueue) or Pub/Sub. The main application should immediately return a `202 Accepted` and offload all processing, validation, and storage to background worker instances.
- **Anti-Pattern (Average of Averages)**: Calculating aggregate metrics (e.g., performance times, success rates) in the application or UI layer by averaging pre-calculated segment averages. This produces statistically invalid metrics that can mislead product decisions.
- **Resolved Pattern**: Push analytical rollups down to the data warehouse (BigQuery). Always calculate true averages by summing the raw base components (e.g., `SUM(total_duration) / SUM(total_events)`) directly in BigQuery via base-component rollups before serving the final metric to the UI.
- **Vitest Environment & Memory Management**: To prevent memory bloat and slash execution time, strictly map non-UI test paths (like `server`, `utils`, `workers`, `firestore`) to the `node` environment via `environmentMatchGlobs` in `vitest.config.ts`. The default `jsdom` environment is extremely heavy. For individual utility tests that actually require DOM globals (like `localStorage` or `document`), override the glob mapping by adding `// @vitest-environment jsdom` at the top of the specific test file. Ensure `isolate: true` is maintained for stability, but protect against runner crash leaks by adding a `process.on('disconnect')` listener in `setupTests.ts` that triggers `process.exit()`.
- **Vitest Zombie Protection & Memory Limit**: When using Vitest with `pool: 'forks'`, memory leaks can crash the parent IDE due to V8's lazy garbage collection. You MUST pass `--max-old-space-size=512` to `execArgv` inside the pool options to cap the heap and force early GC. Additionally, `process.on('disconnect')` is unreliable if the parent is killed via OOM `SIGKILL`. Implement asynchronous PPID polling via `setInterval` in `setupTests.ts` (checking if `process.ppid !== originalPpid` or `process.ppid === 1`). If orphaned, the worker MUST issue `process.kill(process.pid, 'SIGKILL')` to terminate itself.
